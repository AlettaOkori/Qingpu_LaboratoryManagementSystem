# 实验教学与资源管理 demo（v9）

这是一个可交互的区校两级实验教学与资源管理 demo，重点覆盖物理实验室业务和通用管理模块。页面使用原生 HTML、CSS 和 JavaScript；业务数据保存在浏览器本地，不连接参考系统或外部服务。

v9 的核心口径是：学校维护的“实验计划”就是实验业务的权威单据，不再单独维护一套全局“实验目录”。底层地点主档独立于设备，任课关系独立于班级，计划独立于班级，预约记录独立于安排记录，完成结果独立为实验总结；设备名称、规格、分类、单位和管理方式直接保存在采购、入库、设备台账、库存及预约明细中。实验流程与参考系统一致，采用“预约→安排→总结→完成”，不设置独立的“准备”动作或“已准备”状态。

详细字段取舍见[字段对照清单](字段对照清单.md)。

学校端“基础档案”的导航口径为：

- “实验室”：实验室档案；
- “人员管理”：人员档案、班级管理、任课教师及任课班级设置。

学校端不再单列“任课关系”页签。管理员在“人员管理 → 任课教师”列表中点击“设置任课班级”，按学期维护教师的班级、学科、主教师和状态；底层关系记录仍用于生成班级实验任务、预约和教学统计。

其中，“实验室”是当前界面名称；底层仍使用 `rooms` 和 `roomId` 表达实验室、准备室、仪器室、普通教室等通用地点，不表示发生了数据迁移。

## 启动

在项目根目录运行：

```sh
python3 -m http.server 8765 --bind 127.0.0.1 --directory new-demo
```

访问 [http://127.0.0.1:8765/](http://127.0.0.1:8765/)。请持续使用同一地址和端口；不同来源的浏览器存储不共享，不建议直接双击 `file://` 页面。

- `index.html`、`login.html`：免密码身份选择入口。
- `pages/district/`：区级管理页面。
- `pages/school/`：学校管理员和任课教师按权限共用的学校页面。
- `preview.html`：内部页面总览，只从“系统控制”进入。

## 当前实现的业务关系

### 实验教学

```text
当前学期＋当前学科
  → 编制实验计划
  → 多条计划明细（实验名称、章节、教材范围、器材需求、课时、分组/演示＋周次或日期）
  → 按有效主教师任课关系自动生成班级实验任务
  → 教师预约申请（日期、节次、分组数、补充器材需求）
  → 学校管理员安排（最终日期、节次、地点、实验室/教室、实验负责人、实际器材）
  → 教师/管理员提交实验总结
  → 对应班级实验任务完成
  → 学校和区级开出统计
```

计划本身不关联班级或任课教师，也没有“已完成”状态。班级和教师通过“学期＋班级＋学科＋教师”的有效主教师任课关系进入自动生成的班级实验任务；协同教师不重复生成应开任务。应开数以这些任务为准，提交总结后才计为实开。同一学校、学期和学科可按年级或教材建立多份计划；系统在所有有效计划明细间禁止重复纳入相同“实验＋类型”，避免重复生成应开分母。

教师交接或旧计划归档后，系统会按“学校＋学期＋班级＋计划实验（名称、章节、教材范围）＋实验类型”识别已完成义务，避免同一实验在同一班级被重复计入应开；未完成任务仍按新的有效主教师关系生成。

学校管理员填写删除原因后，可删除尚未产生预约、安排、总结、库存流水或附件的实验计划；删除计划会同时删除其计划明细和未开展的班级任务。已产生业务痕迹的计划不能删除，只能归档保留历史。班级实验任务仅允许删除“待预约／已失效”且没有任何关联业务记录的任务；已取消、待安排、已安排或已完成任务保留原记录。

删除班级任务后，系统记录该“计划明细＋任课关系”的删除标记，后续任课关系同步不会把它自动重生；如需恢复，应由管理员重新编制计划明细或通过正式恢复流程处理。

计划表单中的学期和学科由页面上下文自动写入；计划头直接保存适用年级和教材版本，计划明细直接保存实验名称、章节、器材需求、课时、必做/选做、分组/演示及建议时间。创建人和发布时间是系统审计字段，不是任课关系。这样计划可以独立解释和归档，不依赖另一个实验目录才能还原业务含义。

预约阶段不选择实验室、最终时间、实验负责人或具体资源，只按与实验学科相容的设备／耗材明细填写补充器材需求数量；表单可动态添加、删除多条计划外器材需求，并保存申请时的班级人数快照。危化品只允许化学实验申请。学校管理员在“安排实验”中确定最终日期、连续启用节次、地点类型、实验负责人和具体资产／库存余额；节次数不少于计划明细课时。地点为“实验室”或“教室”时房间必填，地点为“其他”时不关联房间、其他地点说明必填。系统同时校验房间容量、学科、班级、教师、实验负责人和资源冲突。

实验总结当前保存实际完成日期、实验效果、改进意见、仪器完好情况、备注，以及可选的 2 张实验全景图和 3 张学生实验图。它只完成对应班级实验任务，不会完成整个计划。

#### 预约与安排页签

“预约与安排”仍是一个模块，使用六个页签切换同一套预约、安排和总结台账；页签只是查询视图，不会产生新的业务单据或状态。

| 页签 | 数据范围 | 说明 |
| --- | --- | --- |
| 已预约实验 | 有效预约且状态为“待安排”或“已退回” | 管理员的待安排工作队列；安排后转入“已安排实验” |
| 已安排实验 | 存在未取消实验安排的预约 | 包含“已安排”和已完成历史，便于追溯；取消安排的记录不显示 |
| 待登记总结实验 | 安排状态为“已安排”且尚无实验总结 | “已安排实验”的待办子集，安排完成后直接进入该页签 |
| 我预约的实验 | 当前账号提交、且仍处于“待安排”或“已退回”的预约 | 教师查看本人待处理预约 |
| 我的已安排实验 | 当前账号是实验负责人或安排人的未取消安排 | 学校管理员按责任范围查看安排及历史 |
| 我的待登记总结实验 | “我的已安排实验”中尚未提交总结的记录 | 个人总结待办子集 |

因此不再单列“完成记录”页签：已完成历史保留在“已安排实验／我的已安排实验”中，可结合状态筛选查看；六个页签之间的切换不会改变预约、安排或总结状态。

### 采购、入库和存放

```text
学校采购申请
  → 区级通过/驳回
  → 整单到货入库
      ├─ 单件编号物品 → 按数量生成资产编号
      │    ├─ 有房间 → 正常使用
      │    └─ 无房间 → 待存放
      └─ 数量库存物品 → 建立或合并库存余额
           ├─ 有房间 → 在库
           └─ 无房间 → 待分配
```

当前系统采用单层存放位置，不显示、不保存橱柜和层次。设备和库存直接关联 `roomId`；入库明细的存放位置可以留空，留空时保留“待存放／待分配”状态。`rooms` 仍可表示实验室、准备室、仪器室、普通教室和其他地点，物品名称、规格、分类、单位和管理方式直接随业务明细保存。

设备／耗材明细支持两种管理方式：

- 单件编号：每件生成独立资产，可查看、维修、维保和报废。
- 数量库存：按物品和房间形成库存余额，支持入库、领用、退回、损耗和处置。

名称、分类编号、规格型号、分类、单位、管理方式和周期维保要求随采购、入库和台账明细保存；已生成资产或库存后不直接改写物品属性，历史单据保留当时快照。

所有危化品库存流水，以及任课教师提交的领用，均须由另一名责任人复核，申请人不能自审。含危化品的入库单按整单原子复核：全部通过才记账并激活暂存资产；任一明细驳回则整单不入账，采购单退回可重新收货。危化品只能放入显式标记为“具备危化品存放条件”的房间，到货时必须登记有效期；未清零的过期余额不能与新到货混存。过期余额不能用于实际安排或领用，只能通过真实退回、损耗和处置清理；阈值维护仍可使用。

实验安排中的数量型耗材必须在提交总结前完成关联领用并记账；关联安排的领用不得超出实际配置数量。取消安排会撤销关联待复核领用；已记账领用必须按原单真实退回，损耗和处置不能冒充退回。

数量库存通过入库、领用、退回、损耗和处置保持余额与流水一致；单件资产可在“设备台账”中查看、维修、维保和报废。

### 安全与资料

```text
区级检查任务
  → 学校检查记录
  → 发现隐患
  → 上传关联整改附件
  → 提交整改
  → 区级复查通过/退回
  → 隐患及检查任务闭环
```

通用资料上传可关联设备资产、采购申请、入库单、设备处理单、实验计划、实验预约、实验安排、实验总结、检查记录、隐患整改和人员；总结表单还会把全景图、学生实验图作为分类附件关联实验总结。原始文件或文本保存在浏览器本地，详情保留处理轨迹。

## 核心基础数据

| 数据 | 当前作用 |
| --- | --- |
| 学校、部门、人员 | 区校范围、人员档案和演示身份 |
| 实验室档案（底层 `rooms`） | 实验地点、存放位置和容量 |
| 班级、任课班级设置 | 按学期和学科确定教师，并生成班级实验任务 |
| 学期、学校节次 | 计划上下文、预约和安排时间；节次按学校和学期分版 |
| 实验计划/计划明细 | 计划名称、适用年级、教材版本，以及实验名称、章节、必做/选做、分组/演示、课时、建议时间和器材需求 |
| 设备／耗材业务明细 | 分类编号、名称、规格、分类、单位、单件/数量管理和维保要求，随采购、入库和台账记录保存 |

实验室档案表单保留名称、类型、实验室号、学科、可用状态、面积、座位数、建造商、建造日期、学段、功能文本、危化品存放条件和备注。教学实验室、准备室和仪器室必须明确学科，普通教室和其他地点可设为通用；面积、座位数不是所有地点的必填项。实验室档案不维护固定管理员；具体实验责任人由实验安排中的“实验负责人”记录。已有存放物品、危化品或有效安排时，相应学科、安全能力、类型、容量和状态受到引用保护。

## 页面与角色

- 区级管理员：跨校查看、采购和报废审批、安全复查、学期及平台设置。
- 学校管理员：本校实验室、人员管理、计划、预约安排、设备库存、采购入库、实验执行协同、安全检查、整改、验收和上报；原实验员职责并入本角色。
- 任课教师：本人学科计划、本人班级任务预约、预约修改、实验总结、资料和耗材领用。

### 演示身份边界

为便于免密码登录和切换角色，当前 demo 仍把人员档案、账号角色和启停状态合并在 `staff` 记录中。这里的“账号角色”只用于前端演示权限，不是生产级用户、角色和菜单授权模型。

真实系统应拆分人员、账号、角色和权限，并由服务端完成登录、鉴权和审计。当前 demo 没有真实用户名密码，也不应录入真实敏感信息。

- 12 个地点档案，其中 9 个教学实验室；
- 6 个班级、18 条有效任课班级设置、48 条按学期分版的学校节次；
- 18 件单件资产、12 条数量库存；
- 9 个实验计划、15 条计划明细、30 条班级实验任务；
- 3 条预约、1 条已安排实验，以及安全、维修、采购和附件样例。

初始区域必做应开 24 次，每校 8 次；尚未提交实验总结，因此初始实开为 0。必做/选做与分组/演示分别统计，分母为 0 时显示“不适用”。

## 推荐演示路线

1. **计划到统计**：学校“实验教学”直接编制实验计划；学期和学科由页面上下文写入，计划头填写年级和教材，明细填写实验名称、章节、器材需求和课时。发布后查看自动生成的班级实验任务。
2. **预约到总结**：从班级实验任务发起预约；可在“补充器材需求”中新增计划外物品和数量；学校管理员安排日期、节次、地点、实验室/教室、实验负责人和器材；安排完成后直接由任课教师提交实验总结，若配置数量型耗材则先完成关联领用记账，观察任务和区校统计更新。
3. **采购到台账**：学校提交采购申请，区级审批，学校到货入库。入库明细直接生成待存放资产或待分配库存，并把名称、规格、分类、单位和管理方式同步写入业务台账。
4. **库存闭环**：对数量库存执行入库、领用、退回、损耗和处置，确认余额、流水和业务单相互对应。
5. **危化品复核**：登记危化品入库或领用，切换另一名学校责任人复核，确认实验室/通用地点安全能力、有效期、复核前后库存及关联单据状态变化。
6. **安全闭环**：学校上传隐患整改附件并提交，区级复查通过或退回，在详情中查看状态和轨迹。

## 数据保存与迁移

- 业务数据使用同源 `localStorage`，当前窗口身份使用 `sessionStorage`。
- v9 仍沿用原存储键，但数据内有 `version: 9`。旧 v2/v3/v4/v5/v6/v7/v8 数据会自动迁移为地点主档、设备／耗材业务台账、任课关系、计划明细、班级任务、安排和总结结构；历史人员培训字段会被清理，历史“已准备”状态会转换为“已安排”，旧准备说明保留到安排说明中；旧全局实验目录会被摊平为计划头/计划明细快照，旧“实验员”身份会合并为学校管理员。
- 系统控制支持 JSON 备份和确认恢复初始数据；当前没有备份文件恢复界面。
- 所有写入先检查浏览器中的数据版本，避免多个页面直接覆盖较新的本地记录。

## 当前边界

- 这是浏览器本地 demo，没有服务端并发、真实鉴权、防篡改审计、灾备或消息通知。
- 计划保存即发布，没有独立草稿编辑和审批界面。
- 采购按整单到货，不支持部分收货或商城流程。
- 导入只支持 UTF-8 CSV。模板列与“新增设备/入库”中的物品明细一致：分类编号、物品名称、规格型号、分类、单位、管理方式、需要周期维保、数量、单价（元）、存放位置（房间）、下次维保日期、有效期；供应商、登记日期、购置日期和备注仍在入库弹窗中填写。
- 当前不建设设备借用归还业务；设备状态只沿设备台账、维修、维保和报废流程变化。
- 实验室/通用地点状态在主档维护，有效安排占用时不能停用；当前没有实验室改造、摄像头和橱柜管理表单。
- 数量库存当前按“物品＋房间”维护余额；正式危化品系统还应进一步拆分批次号、批次有效期和近效期优先出库。
- 计划明细的器材需求按学校业务填写为文本；预约支持从设备／耗材业务明细动态添加补充器材及数量，管理员安排时再选择当前可用资产和库存。补充需求不提前预占库存，。
- 通用附件约 512 KB 以内；总结图片另按单张数据大小限制保存在浏览器。不要上传真实敏感资料。
- 统计、智能问数和 HTML 报告只使用当前本地台账，不代表正式监管口径或合规结论。
