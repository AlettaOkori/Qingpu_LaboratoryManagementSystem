# 实验教学与资源管理 demo（v12）

这是一个可交互的区校两级实验教学与资源管理 demo，覆盖科学、物理、化学和生物学实验教学及通用管理模块。页面使用原生 HTML、CSS 和 JavaScript；业务数据保存在浏览器本地，不连接参考系统或外部服务。

v12 的核心口径是：学校按参考系统流程选择教材实验清单编制“实验计划”，计划项明确区分“必做、选做、创新实验”，计划的适用班级另存为独立关系。官方目录实验和学校自定义创新实验均在发布时形成计划快照；自定义创新实验支持章节、实施方式和结构化器材需求，可使用尚未建档的器材，但不会自动改写设备或库存台账。底层地点主档独立于设备，房间下增加橱柜主档，资产和库存以 `roomId + cabinetId` 表达精确存放位置；任课关系独立于班级，预约记录独立于安排记录，完成结果独立为实验总结；实验流程采用“预约→安排→总结→完成”。易耗品管理和维修报废严格按参考系统收敛，教学资源采用独立资源库，教师上传后立即入库。

演示数据覆盖科学、物理、化学、生物学四个学科以及高一、高二、高三三个年级；切换适用年级后，教材、官方实验目录和适用班级会同步切换。已打开过旧版本 Demo 的本地数据也会在升级时自动补齐缺少的年级示例和科学学科业务链。

详细字段取舍见[字段对照清单](字段对照清单.md)。危化品对象关联与两级审核闭环见[当前 Demo 业务流程与数据关系闭环评估报告](当前Demo业务流程与数据关系闭环评估报告.md)。

导航按角色的工作对象重新分组：

| 角色 | 导航分组 |
| --- | --- |
| 区级管理员 | 工作台；组织与配置；教学监管；资产监管；安全监管 |
| 学校管理员 | 工作台（含教学资源库）；教学运行；资产物资；安全管理；基础设置 |

### 两级总览与教师工作台

总览是现有业务台账的只读投影，不新增汇总表，也不在页面中复制维护统计值。区域、学校和教师看到的卡片、待办与下钻记录由同一个 `overview()` 口径生成；学期、学校和学科范围改变后同步重算，业务处理仍回到原始单据并按原权限校验。

| 使用角色 | 首要问题 | 页面主体 | 主要去向 |
| --- | --- | --- | --- |
| 区级管理员 | 哪些学校需要介入 | 必做开出率、需关注学校、教学超期、区级待办、上报异常；学校教学与风险态势表；资源、安全、上报与配置质量 | 实验开出统计、学校与上报、危化品安全监管 |
| 学校管理员 | 今天和本周要保障什么 | 本周实验运行、待安排／待总结、分学科执行进度、资源异常、安全闭环、配置缺口与上报状态 | 实验计划、预约与安排、资源及安全业务台账 |
| 任课教师 | 我接下来要上什么实验 | 本人本周实验、退回预约、待登记总结、计划超期、本人班级执行进度 | 本人实验计划、本人预约、教学资源库 |

区域端按学校并排展示“教学进度＋超期＋资源／安全＋配置＋上报”，默认把有异常的学校排在前面；待办只纳入区级能够处理的采购审批和待区级复查隐患。学校管理员的优先待办同时覆盖实验安排与总结、待检查、待整改／校内复核、库存复核及采购后续。教师工作台只读取本人任课、预约、安排和总结，不显示学校管理类资源、安全、配置或上报数据。

教学和资源指标服从顶部学科范围；安全隐患、危化品和专项检查按学校或区域共享，不随学科筛选。必做“实开”仍以提交实验总结并同步完成班级执行记录为准；本周实验按管理员最终安排日期统计，不按教师申请日期统计。所有总览均明确展示统计日期、周次、周范围和当前数据版本。

区级将“实验计划监管”和“实验开出统计”拆成两个入口，分别查看教学来源单据和统计结果。学校端的“实验室档案”“人员与班级”“危化品安全管理”属于管理员配置或管理职责，不向任课教师显示；教师仍可直接使用实验计划、预约与安排、设备与入库、易耗品账目、维修与报废和教学资源库。导航隐藏只减少无关入口，页面和业务操作仍继续执行原有角色权限校验。

学校端不再单列“任课关系”页签。管理员在“人员与班级 → 任课教师”列表中点击“设置任课班级”，按学期维护教师的班级、学科、主教师和状态；底层关系记录用于确定各班实验计划执行人、预约范围和教学统计。

学校端所有业务表单和日常运行列表均以当前登录学校为数据范围，不展示“学校”选择字段或学校列；学校归属由账号上下文自动写入。跨校选择仅保留在区级管理端。

其中，“实验室档案”是当前导航名称；底层使用 `rooms` 和 `roomId` 表达实验室、准备室、仪器室、普通教室等通用地点，`cabinets` 和 `cabinetId` 表达房间内橱柜。橱柜编号在学校内唯一，必须隶属于本校房间；危化品专用柜只能建在具备危化品存放条件的房间。

### 学科工作范围

四个学科使用同一套导航和业务模块，不为每个学科复制一套菜单，也不在每个功能模块右上角设置互相独立的切换按钮。需要分科的数据页面共用顶部上下文栏中的唯一“学科范围”；切换后会同步影响当前页面列表、统计和可选器材，并在跨页面访问时沿用。学校管理员和区级管理员可选择“全部学科”。任课教师的可选范围是其专业学科与当前学期有效任课关系中学科的并集；专业学科为“综合”的教师只按当前学期有效任课关系确定范围，教师不能选择“全部学科”。

危化品安全管理是跨学科共享模块，不显示“学科范围”切换，也不因用户在其他页面选择了某个学科而过滤危化品台账、检查和整改记录。学校档案、人员、班级、学期和系统设置同样保持跨学科共享。

### 危化品安全管理

安全页面以危化品库存、专用柜和存放房间为工作对象，提供危化品台账、隐患与整改、专项检查台账、检查任务及危化品库存流水入口。学校管理员可处理待复核的危化品流水，也可在隐患列表和详情对待校内复核的整改执行“通过／驳回”；这两种审核分别改变库存业务与隐患状态。页面概览集中提示待办、有效期、存放与未关闭隐患；低于库存阈值属于补库提醒，不能直接认定为安全隐患。

专项检查必须明确业务范围和对象：危化品库存记录、危化品专用柜或具备危化品存放条件的房间。库存问题只关联选中的库存；柜体、存放环境问题按明确选定的柜或房间关联受影响危化品。一般房间维修隐患保留为一般安全记录，不会仅因“同一房间”出现在危化品详情或风险数量中。例如，缺少危化品范围和对象依据的“化学准备室房间门锁损坏”不会自动关联到某一瓶试剂；明确登记为危化品专用柜锁具或存放环境出入控制问题时，才按该对象关联。

检查项目按账物数量、存放条件、包装标签、有效期、领用复核和待处置物品逐项勾选，并可补充其他项目。一次检查可以分行登记多项隐患，每项继承本次检查对象；不同对象的问题分别建检查记录。整改须有说明与关联附件，提交后先进入“待校内复核”。无论隐患来自区级任务还是学校自查，学校管理员通过后均进入“待区级复查”，再由区级管理员最终通过或驳回；只有区级复查通过后才关闭隐患。任一级驳回均回到“整改中”，重新提交仍须先经过校内复核。每次通过和驳回均填写意见并保留审核人、时间、阶段和结果；同一任务的全部隐患关闭后才完成。

业务学科为科学、物理、化学、生物学。内部规范值分别为“科学”“物理”“化学”“生物”，并映射到稳定代码 `SCI`、`PHY`、`CHEM`、`BIO`；历史数据中的“生物”和别名继续兼容，界面统一显示“生物学”。“通用/跨学科”只表示器材资源可被多个学科使用，不作为第五个学科。

设备、库存、采购／入库明细、库存流水快照和预约补充器材会显式保留资源适用范围：`subjectScopes` 保存一个或多个适用学科，`shared: true` 或兼容字段 `subjectScope: "通用"` 表示跨学科共享；学科仪器也可由“科学仪器／物理仪器／化学仪器／生物仪器”分类确定范围，危化品只用于化学。为兼容当前 demo 的历史普通耗材，既没有上述范围字段、又不是学科仪器或危化品的普通耗材暂按通用资源处理；这是 demo 默认兼容规则，不应被理解为生产数据可以省略资源范围。

## 启动

在项目根目录运行：

```sh
python3 -m http.server 8765 --bind 127.0.0.1 --directory new-demo
```

访问 [http://127.0.0.1:8765/](http://127.0.0.1:8765/)。请持续使用同一地址和端口；不同来源的浏览器存储不共享，不建议直接双击 `file://` 页面。

- `index.html`：默认进入学校管理端首页。
- `login.html`：免密码身份选择入口。
- `pages/district/`：区级管理页面。
- `pages/school/`：学校管理员和任课教师按权限共用的学校页面。
- `preview.html`：内部页面总览，只从“系统控制”进入。

## 当前实现的业务关系

### 实验教学

```text
当前学期＋学科＋年级＋教材
  → 从教材实验清单勾选计划项（必做／选做／创新实验）
  → 选择适用班级并填写分组/演示、周次或日期
  → 按适用班级分别形成班级执行记录（内部数据）
  → 教师预约申请（日期、节次、分组数、补充器材需求）
  → 学校管理员安排（最终日期、节次、地点、实验室/教室、实验负责人、实际器材）
  → 教师/管理员提交实验总结
  → 对应班级执行记录完成
  → 学校和区级开出统计
```

新建或修改计划时，适用班级通过独立关系 `planTargets` 显式保存；系统只为这些班级中匹配“学校＋学期＋学科”的有效主教师任课关系建立内部班级执行记录。计划页面是用户管理教学要求的唯一入口，不再单列“班级实验任务”或“我的任务”页签。计划列表汇总应开次数和完成进度，计划详情展示各班执行情况并提供“预约实验”操作。协同教师不重复计入应开，应开数按必做、选做、创新实验分别统计，提交总结后才计为实开。

教师交接或旧计划归档后，系统会按“学校＋学期＋班级＋计划实验（名称、章节、教材范围）＋实验类型”识别已完成义务，避免同一实验在同一班级被重复计入应开；未完成记录仍按新的有效主教师关系建立。

学校管理员填写删除原因后，可删除尚未产生预约、安排、总结、库存流水或附件的实验计划；删除计划会同时删除其计划实验和未开展的班级执行记录。已产生业务痕迹的计划不能删除，只能归档保留历史。系统不提供单独删除班级执行记录的界面，班级范围和未开展记录统一通过实验计划维护，已有预约或完成历史继续保留。

计划表单中的学期由当前学期上下文写入；学科默认沿用顶部“学科范围”，若当前为“全部学科”，则在编制表单中选择一个具体学科。这里的学科字段只确定本计划归属，不形成计划模块自己的页面切换状态；年级和教材也由编制页选择。新建计划名称默认采用“学期 · 年级学科实验计划”（如“2026-2027学年第一学期 · 高一物理实验计划”），列表、详情和表单使用同一名称；用户仍可按业务需要修改名称。计划头保存 `textbookId` 和适用年级，适用班级逐条保存到 `planTargets`；计划明细保存 `sourceType/sourceId`、`experimentCategory`、实验名称、章节、器材快照、课时、分组/演示及建议时间。创建人和发布时间是系统审计字段，不是任课关系；已发布计划保留当时实验和器材快照。

预约阶段不选择实验室、最终时间、实验负责人或具体资源，只按与实验学科相容的设备／耗材明细填写补充器材需求数量；表单可动态添加、删除多条计划外器材需求，并保存申请时的班级人数快照。危化品只允许化学实验申请。学校管理员在“安排实验”中确定最终日期、连续启用节次、地点类型、实验负责人和具体资产／库存余额；节次数不少于计划明细课时。地点为“实验室”或“教室”时房间必填，地点为“其他”时不关联房间、其他地点说明必填。系统同时校验房间容量、学科、班级、教师、实验负责人和资源冲突。

实验总结当前保存实际完成日期、实验效果、改进意见、仪器完好情况、备注，以及可选的 2 张实验全景图和 3 张学生实验图。它只完成对应班级的计划实验，不会把整个计划标记为完成。

#### 预约与安排页签

“预约与安排”仍是一个模块，使用六个页签切换同一套预约、安排和总结台账；页签只是查询视图，不会产生新的业务单据或状态。

| 页签 | 数据范围 | 说明 |
| --- | --- | --- |
| 已预约实验 | 有效预约且状态为“待安排”或“已退回” | 管理员的待安排工作队列；安排后转入“已安排实验” |
| 已安排实验 | 存在未取消实验安排的预约 | 包含“已安排”和已完成历史，便于追溯；取消安排的记录不显示 |
| 待登记总结实验 | 安排状态为“已安排”且尚无实验总结 | “已安排实验”的待办子集，安排完成后直接进入该页签 |
| 我预约的实验 | 当前账号提交、且仍处于“待安排”或“已退回”的预约 | 教师查看本人待处理预约 |
| 我的已安排实验 | 当前账号是实验负责人或安排人的未取消安排 | 学校管理员按责任范围查看安排及历史 |
| 我的待登记总结实验 | “我的已安排实验”中尚未提交总结的记录 | 个人总结待办子集 |

因此不再单列“完成记录”页签：已完成历史保留在“已安排实验／我的已安排实验”中，可结合状态筛选查看；六个页签之间的切换不会改变预约、安排或总结状态。

### 采购、入库和存放

```text
学校采购申请
  → 区级通过/驳回
  → 整单到货入库
      ├─ 单件编号物品 → 按数量生成资产编号
      │    ├─ 有房间 → 正常使用
      │    └─ 无房间 → 待存放
      └─ 数量库存物品 → 建立或合并库存余额
           ├─ 有房间 → 在库
           └─ 无房间 → 待分配
```

系统采用“房间 → 橱柜”的两级存放位置，不实现橱柜内层次。设备和库存保存 `roomId`，分配到具体柜位时同时保存 `cabinetId`；只选择房间表示直接存放，位置为空时保留“待存放／待分配”状态。入库、设备台账和库存列表统一显示“房间 / 橱柜”，物品名称、规格、分类、单位和管理方式直接随业务明细保存。橱柜详情支持按当前台账生成并下载 HTML 柜卡，不另存一套库存数据。

设备／耗材明细支持两种管理方式：

- 单件编号：每件生成独立资产，可查看，并在维修报废模块登记维修或报废。
- 数量库存：按物品、房间和橱柜形成库存余额，支持入库、领用、退回、损耗、处置和管理员移柜；移柜保留独立的存放位置调整记录。

名称、分类编号、规格型号、分类、单位、管理方式和周期维保要求随采购、入库和台账明细保存；已生成资产或库存后不直接改写物品属性，历史单据保留当时快照。

所有危化品库存流水，以及任课教师提交的领用，均须由另一名责任人复核，申请人不能自审。含危化品的入库单按整单原子复核：全部通过才记账并激活暂存资产；任一明细驳回则整单不入账，采购单退回可重新收货。危化品只能放入显式标记为“具备危化品存放条件”的房间，到货时必须登记有效期；未清零的过期余额不能与新到货混存。过期余额不能用于实际安排或领用，只能通过真实退回、损耗和处置清理；阈值维护仍可使用。

实验安排中的数量型耗材必须在提交总结前完成关联领用并记账；关联安排的领用不得超出实际配置数量。取消安排会撤销关联待复核领用；已记账领用必须按原单真实退回，损耗和处置不能冒充退回。

数量库存的入库、领用和退回继续服务实验执行；“易耗品账目”页面严格采用参考系统的易耗品总账、分类账和损耗登记。损耗登记按“选择仪器设备 → 在明细中填写损耗数量 → 选择或录入损耗原因”办理，经办人由当前账号带出且只读；保存后直接扣减现有数量，删除登记时恢复数量。

### 教学资源库

“教学资源库”是教学设计、教案、学案、课件、实验视频和学习单的统一入口。教师上传时必须填写资源名称、资源类型、学科、适用年级和实验属性，保存后资源立即进入本校资源库，不再经过“待整理历史资料”或管理员确认归档。资源列表支持按资源类型、学科、年级和实验属性组合检索，并提供预览、下载和批量下载。

实验属性固定为“必做、选做、创新实验”，适用年级支持多选。教师可以修改或删除本人上传的资源；学校管理员可以修改和删除本校资源，并补齐或更正标签。文件原文保存在浏览器本地资源文件存储中，文本、图片、PDF和视频可在详情中预览，Office 文件可下载后打开。

业务附件仍仅用于检查整改、实验总结等业务单据的关联留痕，底层表名为 `archives`，不再承担教学资源库的上传和整理流程。

### 危化品安全与资料

安全检查、隐患和整改按学校或区域形成统一台账，是跨学科共享数据；安全模块不显示顶部学科切换。危化品工作队列按显式业务范围筛选，一般安全历史保留查询与处理入口。

```text
危化品库存／专用柜／存放房间
  → 区级下发专项检查或学校自查（明确检查对象）
  → 核对账物、存放和有效期，发现一项或多项隐患
  → 整改说明＋关联附件 → 待校内复核
      ├─ 学校管理员驳回 → 整改中 → 重新提交校内复核
      └─ 学校管理员通过 → 待区级复查
           ├─ 区级管理员驳回 → 整改中 → 重新提交校内复核
           └─ 区级管理员通过 → 已关闭
  → 同一任务全部隐患关闭 → 任务完成
```

“危化品库存流水”的待复核入库、领用、退回、损耗和处置继续使用第二人复核规则，通过后才统一记账，驳回保留原库存。库存复核不会替代整改验收，整改通过也不会自动调整库存数量。

通用资料上传可关联设备资产、采购申请、入库单、设备处理单、实验计划、实验预约、实验安排、实验总结、检查记录、隐患整改和人员；总结表单还会把全景图、学生实验图作为分类附件关联实验总结。原始文件或文本保存在浏览器本地，详情保留处理轨迹。

## 核心基础数据

| 数据 | 当前作用 |
| --- | --- |
| 学校、部门、人员 | 区校范围、人员档案和演示身份 |
| 实验室档案（底层 `rooms`） | 实验地点、存放位置和容量 |
| 班级、任课班级设置 | 按学期和学科确定各班实验计划执行教师 |
| 学期、学校节次 | 计划上下文、预约和安排时间；节次按学校和学期分版 |
| 实验计划/计划明细 | 计划名称、适用年级、教材版本，以及实验名称、章节、必做/选做、分组/演示、课时、建议时间和器材需求 |
| 设备／耗材业务明细 | 分类编号、名称、规格、分类、单位、单件/数量管理和维保要求，随采购、入库和台账记录保存 |

实验室档案表单保留名称、类型、实验室号、学科、可用状态、面积、座位数、建造商、建造日期、学段、功能文本、危化品存放条件和备注。教学实验室、准备室和仪器室必须明确学科，普通教室和其他地点可设为通用；面积、座位数不是所有地点的必填项。实验室档案不维护固定管理员；具体实验责任人由实验安排中的“实验负责人”记录。已有存放物品、危化品或有效安排时，相应学科、安全能力、类型、容量和状态受到引用保护。橱柜档案维护编号、名称、所属房间、类型、启用状态、保管责任人和危化品专用标识；设备和库存可在详情或位置调整操作中移动到同校合规房间及橱柜。

## 页面与角色

- 区级管理员：在组织配置、教学监管、资产监管和安全监管中跨校查看、采购审批，对所有已通过校内复核的隐患进行最终通过／驳回。维修和报废仅查看登记，不另设区级审批。
- 学校管理员：维护本校实验室档案、人员与班级、计划、预约安排、设备库存、采购入库、实验执行协同、安全检查、整改、校内复核和上报；可对待校内复核的隐患执行通过／驳回，不能越级完成最终的区级复查。原实验员职责并入本角色。
- 任课教师：使用教学运行、资产物资和教学资源库入口，查看本人相关实验计划并从班级执行情况发起预约，完成预约修改、实验总结、教学资源和耗材领用。

### 管理员更正与删除规则

管理员现在可以从各业务列表直接进入“修改／删除”，但修改不会绕过历史保护，删除也不是无条件物理删除：

| 数据范围 | 可修改 | 可删除或回退 |
| --- | --- | --- |
| 学校、部门、人员、实验室、橱柜、班级、任课班级、学期、节次 | 可编辑未被历史业务锁定的属性 | 没有任何下游引用时可删除；已有引用时提示停用或保留 |
| 采购申请 | 待审核时可修改原申请字段 | 待审核、已驳回或已撤销且无入库单、附件时可删除 |
| 入库单 | 已入库或待库存复核时可更正供应商、登记日期、购置日期和备注 | 无维修报废、实验安排、附件等下游使用时可整单删除；同步冲销库存、移除所生成资产并把采购恢复为待入库 |
| 设备台账／库存 | 非待复核、非已报废设备可调整房间和橱柜；设备可修改下次维保日期，库存可编辑阈值 | 不单独删除资产；错误入库须从入库单统一回滚，正常退出按报废登记处理；移柜写入位置调整记录 |
| 实验计划、预约、安排、总结 | 无执行痕迹的计划可修改并重建未开展的班级执行记录；待安排／已退回预约可修改；未完成安排可修改；总结可更正 | 无下游记录时可删除；删除总结会把安排、预约和班级执行状态统一恢复为“已安排” |
| 检查任务、检查记录、隐患、待归档业务附件 | 在对应未完成状态下可修改 | 无隐患、附件或其他下游引用时可删除，并同步恢复上游状态 |
| 维修、报废、易耗品损耗 | 继续严格使用参考系统字段；维修登记可修改 | 维修、报废和损耗按参考系统提供删除，报废删除恢复设备状态，损耗删除恢复现有数量 |

除参考系统直接登记页外，删除操作要求填写原因并写入操作日志。每次事务写入前都会执行全库关系审计；一旦发现重复 ID、悬空外键、负库存或总结状态不同步，本次修改不会保存。

### 演示身份边界

为便于免密码登录和切换角色，当前 demo 仍把人员档案、账号角色和启停状态合并在 `staff` 记录中。这里的“账号角色”只用于前端演示权限，不是生产级用户、角色和菜单授权模型。

真实系统应拆分人员、账号、角色和权限，并由服务端完成登录、鉴权和审计。当前 demo 没有真实用户名密码，也不应录入真实敏感信息。

## 推荐演示路线

1. **计划到统计**：可先在顶部上下文栏选择具体“学科范围”，再进入学校“实验计划”编制计划；若保留“全部学科”，则在表单内选定本计划学科。学期由页面上下文写入，计划头填写年级和教材，并把所选适用班级显式保存到 `planTargets`。发布后直接在计划详情查看各班执行进度，区级从“实验计划监管”和“实验开出统计”分别追溯来源与结果。
2. **预约到总结**：在实验计划详情的“班级执行情况”中点击“预约实验”，也可从“预约与安排”集中新增预约；补充计划外物品和数量后，由学校管理员安排日期、节次、地点、实验负责人和器材。安排完成后由任课教师提交实验总结，若配置数量型耗材则先完成关联领用记账，观察计划进度和区校统计更新。
3. **采购到台账**：学校提交采购申请，区级审批，学校到货入库。入库明细直接生成待存放资产或待分配库存，并把名称、规格、分类、单位和管理方式同步写入业务台账。
4. **易耗品与维修报废**：在“易耗品账目”查看总账和分类账，登记一次易耗品损耗并核对现有数量；在“维修与报废”分别填写参考字段，确认维修不改变设备状态、报废保存后设备直接变为已报废。
5. **危化品复核**：登记危化品入库或领用，从安全页面的危化品库存流水进入待复核记录，切换另一名学校责任人分别演示通过和驳回，核对库存、关联单据与复核意见；库存审批和整改审批分别呈现。
6. **危化品安全闭环**：先确认普通门锁历史隐患没有串入危化品详情，再针对一条库存的包装标签问题开展自查；上传证据提交后，由学校管理员在列表或详情先驳回、重新提交再通过，查看关闭与审核历史。再用区级任务登记两项隐患，分别完成校内审核，演示区级驳回后重新走校内审核，并验证最后一项关闭时任务才完成。用专用柜或存放房间检查核对对象范围与受影响库存。
7. **教学资源调用**：进入“教学资源库”，教师上传教学设计、教案、学案、课件、实验视频或学习单，补齐学科、年级和实验属性标签后立即检索、预览或下载；管理员可直接修订标签和文件信息。

## 数据保存与迁移

- 业务数据使用同源 `localStorage`，当前窗口身份使用 `sessionStorage`。
- v12 仍沿用原存储键，但数据内有 `version: 12`。旧 v2 至 v11 数据会自动迁移；其中旧维修、维保、报废状态记录会转换为维修或报废直接登记，取消和驳回记录不进入当前登记台账，维修中的资产恢复正常使用，生效的报废登记直接对应已报废资产；旧损耗记录移除复核和状态字段。迁移会补齐橱柜主档和 `storageMoves` 表，并保留没有柜位的历史记录为房间直接存放。教学资源使用独立 `resources` 表，教师上传后不进入历史待整理队列。
- 迁移会把旧版实验目录转换为教材与官方实验目录，并清理不存在入库单的历史可选来源编号；迁移完成和每次业务提交后都必须通过关系审计，避免悬空引用继续写入本地数据。
- 安全记录补齐显式业务范围与对象关联。历史检查、隐患没有可靠危化品对象依据时保留为一般安全记录，原 ID、整改附件和操作日志继续保留，不依据房间名称或隐患描述自动认定为危化品问题。历史已完成结果不改写；未完成整改统一先进入校内复核，校内通过后再进入区级复查。
- 已由较早 v11 打开的初始演示库也会执行幂等补齐：在识别为 demo 初始数据且尚未完成学科模型补齐时，为每校补充缺失的科学教师、科学实验室、科学设备、当前学期有效任课、科学计划、`planTargets`、计划实验和内部班级执行记录，同时补齐三个年级的教材与目录选择。补齐会优先复用已有记录并避免重复；完成标记写入后，不会在后续打开时反复重建用户主动删除的示例。
- 系统控制支持 JSON 备份和确认恢复初始数据；当前没有备份文件恢复界面。
- 所有写入先检查浏览器中的数据版本，避免多个页面直接覆盖较新的本地记录。

## 当前边界

- 这是浏览器本地 demo，没有服务端并发、真实鉴权、防篡改审计、灾备或消息通知。
- 计划保存即发布，没有独立草稿和审批界面；管理员只能在尚无预约、安排、流水、附件或已完成班级执行记录时更正已发布计划。
- 采购按整单到货，不支持部分收货或商城流程。
- 导入只支持 UTF-8 CSV。模板列与“新增设备/入库”中的物品明细一致：分类编号、物品名称、规格型号、分类、单位、管理方式、需要周期维保、数量、单价（元）、存放位置（房间）、橱柜编号（可选）、下次维保日期、有效期；兼容旧版12列表头。填写橱柜编号时必须同时填写所属房间；供应商、登记日期、购置日期和备注仍在入库弹窗中填写。
- 当前不建设设备借用归还业务；维修登记不改变设备状态，报废登记保存后直接把对应设备标记为已报废。
- 实验室/通用地点状态在主档维护，有效安排占用时不能停用；橱柜档案在基础设置中维护，启用状态和房间归属参与存放校验，当前仍没有实验室改造和摄像头配置表单。
- 数量库存当前按“物品＋房间＋橱柜”维护余额，有效期是余额的管理属性；危化品工作队列提示有效期、存放与明确关联的未关闭隐患，库存阈值用于补库。正式危化品系统仍应扩展批次号、批次有效期、近效期优先出库、SDS、相容性管理和危废处置联单。
- 检查对象与校内／区级复核是本次确认的 Demo 业务模型；页面“通过”和“已关闭”表示演示流程结果，不构成现实场所或物品已经安全、合规的判断。
- 计划明细的器材需求按学校业务填写为文本；预约支持从设备／耗材业务明细动态添加补充器材及数量，管理员安排时再选择当前可用资产和库存。补充需求不提前预占库存。
- 业务附件约 512 KB 以内；教学资源单个文件最大100MB，文件存放在浏览器本地资源存储中。不要上传真实敏感资料。
- 统计、智能问数和 HTML 报告只使用当前本地台账，不代表正式监管口径或合规结论。
