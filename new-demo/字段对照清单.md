# v12 表单字段与数据关系对照

核对日期：2026-09-04。

核对范围为参考系统可见的物理实验室和通用模块，以及当前 `new-demo` v12 对科学、物理、化学、生物学四个学科的统一实现。参考系统截图仍以物理流程作为字段核对基线，四个学科复用同一套业务结构，不在本文重复列四套表单。参考系统未展示的下拉枚举、后台必填规则和审批条件，不作为已确认事实。

本次对当前部署版本重新核验后，确认以下页面事实：

- “任课教师设置（物理）”页面以年级为入口，维护班级名称和任课教师；页面没有学期、学科、主教师和状态字段。
- “编制实验计划（物理）”页面显示当前学期，并包含选择年级、计划名称、可选教材、适用班级和实验条目；教材落在实验条目维度。
- 预约与安排仍是两个业务动作，但统一放在“预约与安排”模块中用页签切换；管理员安排时才确定最终地点和时间。
- 当前部署仍保留“橱柜登记（物理）”“存放到橱柜（物理）”“橱柜卡”等页面，并在橱柜存放明细中使用“层次”。新 demo 已保留柜主档、按柜存放和按台账动态生成 HTML 柜卡；柜内层次和二维码仍不作为本轮数据字段。

本文状态含义：

- **保留**：参考字段在 demo 中以相同或等价语义使用。
- **上下文自动写入**：界面只读展示或不显示，保存时由当前学校、学期、学科或账号写入。
- **筛选不入库**：只用于缩小可选范围，不在业务记录中重复保存。
- **删除／拆分**：从原表单移走，或改由独立关系、独立业务记录表达。
- **新增**：参考截图中未出现，但当前 demo 为本地业务闭环实际增加的字段。

## 1. 已确定的统一规则

### 1.1 界面称“实验室”，底层统一使用 `rooms`/`roomId`

参考系统在入库、存放、调整、报废等页面使用“房间或橱柜”和“层次”。当前 demo 的“实验室档案”入口只提供实验室档案；“班级管理”和“任课教师设置”归入“人员与班级”。

为兼容教学实验室、准备室、仪器室、普通教室和其他地点，底层数据表仍使用 `rooms`，资产和库存仍通过 `roomId` 关联位置。这里的“实验室”是学校端主档入口的界面名称，不表示发生了数据迁移。

当前 demo 已作如下统一：

- 用户界面、台账和业务关系使用两级“存放位置”：房间为一级，橱柜为房间内可选的二级位置；不实现橱柜内层次。
- 新增 `cabinets` 橱柜主档和 `storageMoves` 存放位置调整记录；柜卡不单独建表，按当前台账动态生成 HTML；不建立橱柜二维码数据。
- 设备和库存关联 `roomId`，分配到柜位时同时保存 `cabinetId`；只选择房间表示直接存放。
- 入库时允许房间和橱柜为空；单件设备进入“待存放”，数量库存进入“待分配”。
- 后续“调整存放位置”由学校管理员选择同校、可用且与物品条件匹配的房间和橱柜；数量库存按物品＋房间＋橱柜合并余额，并保留调整日志。

### 1.2 表单值只保留一个权威来源

- 实验名称、章节、年级、教材、器材需求和课时从官方实验目录或学校自定义创新实验带入，发布时快照到计划明细；自定义创新实验可维护未建档器材。
- 分类编号、物品名称、规格、分类、单位、跟踪方式和维保要求直接随采购、入库和台账明细保存。
- 班级、教师和学科关系来自任课班级设置。
- 节次的开始、结束时间来自学校节次。
- 计划、预约、安排和总结不重复抄写上述主数据，只保存关联ID和必要业务快照。

### 1.3 修改、删除与引用保护

修改和删除使用原表单字段，不为实现“可编辑”另建修订状态或隐藏字段。统一规则如下：

| 对象 | 修改口径 | 删除口径 |
| --- | --- | --- |
| 基础档案 | 保留原编辑表单；已被任务、库存、安排等引用的关键属性锁定 | 仅无下游引用时删除；有历史时使用停用或保留记录 |
| 采购申请 | 仅“待审核”可修改原申请字段 | 待审核、已驳回、已撤销且无入库单和附件时可删除 |
| 入库单 | 已入库或待库存复核时，只更正供应商、登记日期、购置日期、备注 | 无维修报废、安排、附件等下游使用时整单回滚资产、库存及流水 |
| 设备台账 | 仅修改存放房间和下次维保日期；已安排设备不能换房间 | 不提供独立资产删除；错误来源由入库单回滚，正常退出由报废登记表达 |
| 计划、预约、安排、总结 | 在尚未形成冲突历史的状态下使用原字段更正 | 无下游记录时删除；删除总结同步把安排、预约、任务恢复为“已安排” |
| 检查、隐患、资料 | 只在未完成、待整改或待归档状态更正 | 有隐患、附件或其他引用时阻止；删除后同步恢复上游检查状态 |
| 维修、报废、易耗品损耗 | 严格使用参考字段；维修登记允许原字段修改 | 按参考系统直接删除，报废回写设备状态，损耗回写现有数量 |

通用删除要求填写原因并记录日志。事务提交前执行全库关系审计，覆盖重复 ID、学校归属、核心外键、库存非负和总结完成状态同步；审计不通过时不写入 `localStorage`。

### 1.4 导航分组与角色可见性

导航按“工作台、组织与配置、教学监管、资产监管、安全监管”分组；实验页面增加“创新实验”入口，计划编制页提供教材目录勾选和适用班级选择。学校管理员按“工作台（含教学资源库）、教学运行、资产物资、安全管理、基础设置”分组。

任课教师复用学校页面，但不显示“危化品安全管理”“实验室档案”“人员与班级”三个管理员入口。隐藏菜单不构成权限控制，页面操作仍按角色、学校和本人数据范围校验。

### 1.5 四学科与统一工作范围

业务学科及显示、存储口径统一如下：

| 界面显示名 | 内部规范值 `subject` | 稳定代码 `subjectCode` | 兼容输入 |
| --- | --- | --- | --- |
| 科学 | 科学 | `SCI` | 科学 |
| 物理 | 物理 | `PHY` | 物理 |
| 化学 | 化学 | `CHEM` | 化学 |
| 生物学 | 生物 | `BIO` | 生物、生物学、生命科学 |

“通用”不是第五个学科。需要分科的数据页面共用顶部上下文栏中的唯一“学科范围”，不在每个功能模块右上角各建一套独立切换状态；切换后统一影响列表、统计和可选器材，并在跨页面访问时沿用。学校管理员和区级管理员可选“全部学科”。任课教师可选其专业学科与当前学期有效任课关系中学科的并集；专业学科为“综合”时，只能使用当前学期有效任课关系中的学科，任课教师均不能选“全部学科”。

危化品安全管理按学校或区域共享，不显示学科切换，也不按其他页面保留的学科值过滤危化品台账、检查、隐患和整改。学校、人员、班级、学期和系统设置等组织配置数据同样保持跨学科共享。

设备、库存及其采购／入库明细、流水快照和预约补充器材按以下字段表达适用范围，并在业务传递中保留：

- `subjectScopes`：显式保存一个或多个适用学科内部值；
- `shared: true`：显式表示跨学科共享；
- `subjectScope: "通用"`：兼容旧数据的通用标记；
- 学科仪器没有显式范围时，可由“科学仪器／物理仪器／化学仪器／生物仪器”分类确定单一范围；危化品限定化学；
- 普通耗材若既没有上述范围字段，又不是学科仪器或危化品，当前 demo 暂按通用资源处理。这只是历史演示数据的默认兼容规则，生产数据仍应显式登记范围，不能把缺值长期等同于通用。

## 2. 通用基础表单

### 2.1 学校档案

| 字段 | v12处理 | 必填 | 原因 |
| --- | --- | --- | --- |
| 学校名称 | 保留 `name` | 是 | 组织主数据 |
| 学校代码 | 保留 `code` | 是 | 校内资产编号和跨校识别 |
| 学段 | 保留 `stage` | 是 | 年级及房间默认学段 |
| 学校归属 | 区级数据范围自动确定 | 自动 | 学校档案本身不再重复选择上级单位 |

当前 demo 未实现参考单位管理中的统一社会信用代码、单位性质、总分校关系等扩展字段。

### 2.2 部门

参考系统有独立部门管理；v11 不再把部门作为人员表单中的自由文本。

| 字段 | v12处理 | 必填 |
| --- | --- | --- |
| 所属学校 | 学校端不展示、不允许选择，由当前登录学校自动写入；区级新增时选择 | 自动/条件必填 |
| 部门名称 | 保留 `name` | 是 |
| 状态 | 新增 `state=启用/停用` | 是 |

同一学校不能存在两个同名部门（无论启用或停用）。

### 2.3 人员档案与登录身份

参考教师档案可见姓名、性别、部门和手机号码。v12 字段如下：

| 字段 | v12处理 | 必填 | 说明 |
| --- | --- | --- | --- |
| 所属学校 | 学校端不展示、不允许选择，由当前登录学校自动写入；区级新增时选择 | 自动/条件必填 | 数据权限边界 |
| 姓名 | 保留 `name` | 是 | 人员基本信息 |
| 性别 | 保留 `sex` | 否 | 未登记不推断 |
| 部门 | 保留为 `departmentId` | 否 | 关联部门主数据 |
| 手机号码 | 保留 `phone` | 否 | demo 不校验真实手机号 |
| 账号角色 | 新增 `role` | 是 | 用于 demo 身份切换与操作权限 |
| 专业／任教学科 | 新增 `subject` | 是 | 专业学科与当前学期有效任课共同确定教师可用学科；“综合”教师只按有效任课确定 |
| 岗位职称 | 新增 `title` | 是 | 人员展示和学校管理员岗位说明 |
| 资质说明 | 新增 `qualification` | 否 | 人员岗位资质的简化记录 |
| 启用账号 | 新增 `enabled` | 否 | 控制 demo 身份是否可进入 |

**当前实现边界**：为便于免密码登录和角色演示，`staff` 仍把人员档案、账号角色和启停状态合在一条记录中。真实系统应拆分人员、账号、角色和权限；当前 demo 没有真实用户名、密码、菜单授权和服务端鉴权。

### 2.4 班级与任课教师设置

参考系统“任课教师设置”按年级维护班级名称和任课教师，页面不显示学期、学科、主教师或状态。当前 demo 在“任课教师”列表中提供“设置任课班级”，将这些补成独立、可追溯的任课班级设置，班级表单不再直接多选教师。

在学校端，班级管理和任课教师设置均位于“人员与班级”页签中；“实验室档案”页不承载班级管理或任课教师设置。

| 表单 | 字段 | 必填 | 处理 |
| --- | --- | --- | --- |
| 班级 | 所属学校、班级名称、年级、学生人数、状态 | 是 | 班级只保存班级自身属性 |
| 任课班级设置 | 学期、班级、学科、任课教师、是否主教师、状态 | 是 | 独立 `assignments` 关系；界面从任课教师进入，学期用于保留历届任课，主教师用于确定应开任务的唯一归属 |

同一学校内班级名称唯一。同一学期、班级和学科只允许一个有效主教师；任课教师必须是本校启用的教师账号。计划发布和新增有效任课班级设置时，系统据此建立内部班级执行记录。班级或任课班级设置一旦用于实验计划执行，不能直接改写会改变历史含义的年级、学期、学科、教师和主教师属性；存在待处理实验时不能停用。

### 2.5 学期与学校节次

| 表单 | 字段 | 必填 | 用途 |
| --- | --- | --- | --- |
| 学期 | 学期名称、开始日期、结束日期 | 是 | 计划上下文、日期范围和统计范围 |
| 学校节次 | 当前学期（上下文）、节次编号、名称、开始时间、结束时间、状态 | 是 | 以“学校＋学期＋节次编号”分版；同版编号和时间段均不得重叠，预约中不重复填写起止时间 |

节次一旦被同学期预约或安排引用，所属学校、学期、编号、起止时间和状态均锁定，防止历史申请与安排时间被基础数据反向改写。

## 3. 实验室、设备与耗材台账

### 3.1 实验室档案（对应参考系统实验室登记，底层为 `rooms`）

| 参考字段或旧demo字段 | v12处理 | 必填 | 原因 |
| --- | --- | --- | --- |
| 名称 | 保留 `name` | 是 | 实验室／通用地点名称 |
| 类型 | 保留 `type` | 是 | 教学实验室、准备室、仪器室、普通教室、其他 |
| 房间号／实验室号 | 新增 `roomNo` | 是 | 实验室及通用地点统一位置编号 |
| 面积 | 保留 `area` | 否 | 参考表单未显示通用必填；填写时须大于0 |
| 座位数 | 保留 `seats` | 否 | 教学安排做容量校验；非教学房间可为空 |
| 建造商 | 保留 `builder` | 否 | 参考字段 |
| 建造日期 | 保留 `builtAt` | 否 | 指主要设施设备建成时间 |
| 特征或功能 | 保留 `features` 文本 | 否 | 参考字段；当前为最多500字的多行文本，不维护预设多选枚举 |
| 备注 | 保留 `note` | 否 | 最多60字 |
| 所属学段 | 保留 `stage` | 否 | 默认取学校学段，可变更 |
| 所属学校 | 学校端不展示、不允许选择，由当前登录学校自动写入；区级新增时选择 | 自动/条件必填 | 避免学校端误选其他学校 |
| 学科 | 显式维护 `subject` | 条件必填 | 教学实验室、准备室和仪器室必填；普通教室和其他房间可留空表示通用 |
| 危化品存放条件 | 新增 `hazardStorage` | 是 | 结构化标识房间是否具备危化品存放条件；危化品专用橱柜还须位于此类房间 |
| 管理员 | 从实验室档案表单删除 | — | 不维护固定实验室管理员；具体实验责任人记录在实验安排 |
| 可用状态 | demo新增 `state=可用/停用` | 是 | 参考登记表单未显示状态；当前地点同时承载排课和存放，须有明确可用性，且有效安排占用时不得停用 |
| 每日开放起止时间 | 删除 | — | 改用学校节次和具体实验安排做冲突校验 |
| 橱柜编号、名称、所属房间、类型、保管责任人、启用状态、危化品专用 | 新增 `cabinets`／`cabinetId` | 条件必填 | 橱柜隶属于房间；危化品专用柜只允许建在具备危化品存放条件的房间；不实现柜内层次 |

参考系统的实验室改造记录和摄像头配置不在当前 demo 表单范围内。

房间已有存放物品时不能直接修改学科；仍有危化品库存时不能取消危化品存放条件；存在有效安排时不能修改类型、学科、座位数或停用。上述限制用于保护存量台账与历史安排，不是参考登记页的原始字段。

### 3.2 设备与耗材业务明细

v11 不设置独立的“物品目录”页面。设备名称、分类编号、规格型号、分类、单位、管理方式、周期维保要求，以及显式资源范围 `subjectScopes/shared/subjectScope`，由采购、入库和库存／设备台账明细直接保存，并在后续业务中保留当时快照。

| 明细位置 | 必填字段 | 业务作用 |
| --- | --- | --- |
| 采购申请明细 | 分类编号、名称、规格型号、分类、单位、管理方式、数量、单价 | 形成采购申请和到货入库依据 |
| 入库明细 | 上述物品字段、房间／橱柜、下次维保日期、有效期 | 生成设备资产或数量库存 |
| 设备台账／库存 | 物品字段、设备编号或库存数量、房间／橱柜、状态 | 追踪当前资产、库存和处理状态；管理员可调整位置并留下 `storageMoves` 记录 |

组合约束：耗材和危化品必须按数量库存管理，危化品另执行双人复核；“需要周期维保”只适用于单件编号设备。表单和事务层都会校验无效组合。
## 4. 采购、入库与存放

### 4.1 采购申请

采购审批是青浦本地业务扩展，不是参考物理模块截图中的核心表单。

| 字段 | v12处理 | 必填 |
| --- | --- | --- |
| 采购用途、申请日期 | 用户填写 | 是 |
| 物品明细（分类编号、名称、规格、分类、单位、管理方式）、数量、单价 | 明细填写 | 是 |
| 名称、分类编号、规格、分类、单位 | 由明细直接填写并写入快照 | 是 |
| 申请人、学校、申请单号、状态 | 当前账号和系统自动写入 | 自动 |
| 存放房间、维保日期 | 采购阶段删除 | — |

学校管理员提交，区级管理员通过或驳回；已通过采购单按当前 demo 规则整单到货，不支持部分收货。

### 4.3 入库后的分流

```text
采购申请
  → 区级审批
  → 到货入库
      ├─ 单件编号物品 → 按数量生成资产编号
      │    ├─ 已选房间 → 正常使用
      │    └─ 未选房间 → 待存放 → 分配存放位置（房间）
      └─ 数量库存物品 → 建立/合并库存余额
           ├─ 已选房间 → 在库
           └─ 未选房间 → 待分配 → 分配房间/合并余额
```

含危化品的到货入库按整单处理：所有数量库存明细先形成待复核流水，单件资产也仅暂存为待复核状态。第二人全部复核通过后才统一记账、激活资产并更新入库单/采购单；任一明细驳回则整单撤销，采购单退回“已通过”以便更正后重新收货，驳回流水保留审计。若同一物品和房间已有未过期余额，合并后以较早有效期作为保守提醒；正式系统仍应按批次拆分。

### 4.5 数量库存与流水

“易耗品账目”只保留参考系统的三个页面：

| 页面或表单 | 当前字段 | 规则 |
| --- | --- | --- |
| 易耗品总账 | 分类编号、名称、规格、单位、上年结转数量／金额、本年增加数量／金额、本年减少数量／金额、本年结存数量／金额 | 按年份和仪器分类查询 |
| 易耗品分类账 | 日期、摘要、单价、增加数量／金额、减少数量／金额、结存数量／金额 | 按年份、仪器分类和仪器名称查询 |
| 易耗品损耗登记 | 损耗日期、所选易耗品明细、损耗原因、经办人；明细列为分类编号、名称、规格、现有数量、损耗数量、单位、单价、总价、购置日期、房间或橱柜 | 保存后直接扣减现有数量；不显示业务类型、关联实验、来源流水、状态、审核人或复核字段 |

交互严格采用参考系统口径：点击“选择仪器设备”，在候选明细的“损耗数量”列直接填写数量，留空表示不选择；返回登记表后仍可修改数量或删除明细。“损耗原因”支持从已有原因中选择或自行录入，“经办人”由当前账号带出且只读。分类编号、名称、规格、单位、单价、购置日期和房间或橱柜来自所选库存台账，不允许另填一套物品主档。

实验安排中的数量型耗材必须存在足量、已记账并关联该安排的领用流水，才能提交实验总结。取消安排时自动撤销关联待复核领用；已记账领用须先按原单全量“退回”。只有退回保存 `sourceFlowId`；入库、领用、损耗和处置不保存来源流水，不能冒充退回。

预约补充需求直接保存设备／耗材明细，不会选中某一批过期余额；预约表单支持动态添加、删除计划外器材行并填写数量。管理员安排时不能选过期危化品库存作为实际器材。过期危化品库存不得领用、新增流水入库或通过在途领用复核；库存流水只允许真实退回、损耗和处置；阈值维护仍可用于存量管理；新到货也不能与尚未清零的过期余额混存。

## 5. 实验教学表单

### 5.1 实验计划

参考系统编制页显示当前学期，并提供年级、计划名称、教材、适用班级和实验条目等内容。当前实现沿用该流程：先在顶部上下文栏确定“学科范围”，再在编制页选择年级和教材，并从教材实验目录勾选计划项；必做、选做、创新实验是独立实验属性，学校自定义创新实验可先在“创新实验”页维护，再编入计划。演示数据覆盖科学、物理、化学、生物学以及高一、高二、高三，切换年级会联动教材、实验目录和适用班级；旧版本地数据升级时会自动补齐缺少的年级选项和科学业务链。

学期由当前系统作用域自动写入；计划学科默认沿用顶部“学科范围”，当范围为“全部学科”时由编制人在表单内选定一个具体学科。该字段只确定计划归属，不在计划模块另建一套页面切换状态。适用班级由编制人显式选择并逐条保存到 `planTargets`；系统只在这些目标班级中匹配同学校、同学期、同学科的有效主教师任课关系并建立内部班级执行记录。界面不单列“班级实验任务”或“我的任务”，各班进度与预约入口统一放在实验计划详情中。

| 页面内容 | v12处理 | 是否写入计划 |
| --- | --- | --- |
| 当前学期 | 页面只读；保存时自动写入 `term` | 是，系统写入 |
| 当前学科 | 默认取顶部“学科范围”；管理员处于“全部学科”时须在表单中选定具体学科，教师只可从专业学科与当前学期有效任课范围中选择，“综合”教师只按有效任课范围选择。保存时写入规范 `subject` 和对应 `subjectCode` | 是，用户确认后系统写入 |
| 适用年级 | 计划头保存 `grade` | 是 |
| 教材版本 | 从所选教材带出并保存 `version`，同时保存 `textbookId` | 是 |
| 计划名称 | 用户填写 `name`；新建时默认采用“学期 · 年级学科实验计划”（如“2026-2027学年第一学期 · 高一物理实验计划”），列表、详情和表单保持一致 | 是 |
| 创建人、创建时间、发布时间、状态 | 系统自动写入 `createdBy/createdAt/publishedAt/state`，用于审计与发布／归档生命周期；`createdBy` 不是任课教师关系 | 自动 |
| 实验名称、章节、器材需求、课时 | 从官方目录或学校自定义实验带入，并在计划明细保存快照 `experimentName/chapter/equipment/periods` | 是 |
| 实验属性 | 保存 `experimentCategory`（必做／选做／创新实验）；`required` 仅保留“必做”兼容别名 | 是 |
| 实验来源 | 保存 `sourceType`（官方目录／学校自定义／历史来源）和 `sourceId` | 是 |
| 实验类型 | 每项选择分组／演示，保存到计划明细 `mode` | 是 |
| 时间填写方式 | 每项选择周次或日期 | 是 |
| 计划周次 | 选择周次时保存 | 条件写入 |
| 计划日期 | 选择日期时保存 | 条件写入 |
| 适用班级 | 多选本校同年级在读班级，并在独立关系 `planTargets` 中逐条显式保存；各班执行进度在计划详情中分别展示 | 是 |
| 任课教师 | 已从计划表单删除 | 否 |
| 计划完成状态 | 不存在 | 否 |

每条计划明细保存 `sourceId`、`sourceType`、`experimentCategory`、`experimentName`、`chapter`、`equipment`、`equipmentRequirements`、`periods`、`mode`、`scheduleType`，并只在 `plannedWeek` 与 `plannedDate` 中写入一种；表单会随时间填写方式禁用另一字段。明细保留教材和实验快照，官方目录或自定义实验变化不会改写已发布计划。

保存按钮的实际语义为“保存并发布”。同一学校、学期和学科可以按年级或教材建立多份计划；为防止应开分母翻倍，所有未归档计划之间都不能重复纳入相同“实验名称＋章节＋教材范围＋实验类型”，计划名称在同一学期和学科内也不能重复。计划归档后，该名称和实验明细可以在新版计划中重新使用。

计划可在没有待处理实验时归档：未开展的班级执行记录转为“已失效”，已完成记录作为历史保留；待安排、待修改或已安排的实验会阻止归档。

学校管理员可在计划没有预约、安排、总结、库存流水、附件、待处理或已完成记录时修改计划；系统删除原未开展的班级执行记录和计划实验，再按更正后的计划内容重建。该操作不增加草稿、修订号或审批字段。

删除由学校管理员执行并要求填写删除原因。只有完全没有预约、安排、总结、库存流水、附件或待处理实验的计划才允许删除，删除时连带移除计划实验和未开展的班级执行记录；已有业务痕迹的计划必须归档。班级执行记录不提供独立删除入口，避免用户在实验计划之外维护另一套对象。

### 5.2 计划实验与班级执行记录

计划发布后，系统把每条计划明细与以下有效任课关系匹配：

- 同一学校；
- 同一学期；
- 同一学科；
- 班级在该计划显式保存的 `planTargets` 中；
- 任课关系为有效主教师（协同教师不进入应开分母）；
- 班级年级与计划头适用年级一致。

匹配后自动建立 `teachingTasks`，字段包括计划实验、任课关系、班级、教师、学期、实验属性、来源和执行状态。它是系统内部的班级执行记录，不作为独立业务对象或单独页签展示；计划详情用它展示各班进度并提供预约入口，统计按必做、选做、创新实验分别计算。

同一班级、学期、计划实验（名称、章节、教材范围）和实验类型若已经完成，即使后续发生教师交接或计划归档重建，也不再重复形成新的应开次数；未完成记录仍随有效主教师任课关系正常建立。

“待安排”和“已退回”预约均可用同一预约字段修改；无安排、库存流水和附件时，学校管理员可删除预约，对应班级执行状态恢复为“待预约”或“已失效”。

### 5.4 实验安排

管理员在“预约与安排”的“已预约实验”页签中打开安排表单，查看预约和计划上下文，并填写：

| 字段 | 必填规则 |
| --- | --- |
| 实际安排日期 | 必填，须在计划学期内 |
| 开始节次、结束节次 | 必填，来自本校启用节次；须连续且数量不少于计划明细课时 |
| 地点类型 | 必填：实验室、教室、其他 |
| 房间 | 实验室／教室时必填；实验室限学科匹配的可用教学实验室，教室限可用普通教室；已登记座位数时须满足班级容量。选择“其他”时禁用并清空 |
| 其他地点说明 | 仅地点类型为“其他”时必填；选择实验室／教室时禁用并清空 |
| 实验负责人 | 必填，限本校启用的学校管理员 |
| 实际配置器材 | 可选；在安排阶段确定实际资源并校验并发占用 |
| 安排说明 | 可选，最多100字 |

系统校验房间容量、实验室学科、班级、教师、实验负责人、房间和器材的时间冲突。学校管理员也可以在安排前退回预约；教师或学校管理员可修改申请日期、节次、分组数、补充器材需求和备注后重新提交。

状态为“已安排”且尚未提交总结的安排可由学校管理员修改，保存时重新执行日期、连续节次、房间容量、人员和资源冲突校验；已有耗材领用时，修改后的配置数量不得低于已领用和待复核数量。

### 5.5 安排后执行与总结前校验

参考系统在“安排实验”后直接进入“登记实验总结”，没有独立的准备表单、准备人或“已准备”状态。当前 demo 同样不抽离准备动作：管理员在安排表单中一次性确认房间、负责人和实际器材；数量型耗材如已配置，须在提交总结前完成关联领用流水的复核和记账。取消安排前，已记账领用必须按原单足量真实退回，待复核领用由系统撤销。

#### 5.5.1 预约与安排页签

预约和安排不拆成两个菜单，统一在“预约与安排”模块中通过页签切换。六个页签均从同一条预约—安排—总结关系计算，不新增重复表或重复状态：

| 页签 | 查询条件 | 与其他页签的关系 |
| --- | --- | --- |
| 已预约实验 | 预约状态为“待安排”或“已退回” | 管理员待安排队列；安排后移出本页 |
| 已安排实验 | 存在状态不是“已取消”的实验安排 | 包含当前已安排和已完成历史 |
| 待登记总结实验 | 安排状态为“已安排”，且没有对应 `summaries.arrangementId` | “已安排实验”的待办子集 |
| 我预约的实验 | `applicantId` 为当前账号，且预约仍为“待安排”或“已退回” | 个人预约待办，不重复显示已安排历史 |
| 我的已安排实验 | 当前账号为 `technicianId` 或 `arrangedBy` | 责任人视图，包含完成历史 |
| 我的待登记总结实验 | 同时满足“我的已安排实验”和“待登记总结实验” | 个人总结待办子集 |

“完成记录”不再单列页签，已完成安排保留在“已安排实验／我的已安排实验”中，通过“已完成”状态筛选查看。页签只改变列表范围，不改变 `bookings`、`arrangements` 或 `summaries` 的业务状态。

### 5.6 实验总结

参考系统展示实验名称、类型、分组数、时间、班级、装置图、器材、实验效果、改进意见、仪器完好情况、备注和分类图片。v12 当前表单如下：

| 字段 | v12处理 | 必填 |
| --- | --- | --- |
| 实验、类型、班级、教师、安排时间、房间、预约分组数、器材需求 | 关联数据只读展示 | 自动 |
| 实际完成日期 | `actualDate`，不得早于安排日期或晚于统计日期 | 是 |
| 实验效果 | `effect` | 是 |
| 改进意见 | `improvement` | 否 |
| 仪器完好情况 | `equipmentCondition` | 是 |
| 备注 | `note` | 否 |
| 实验全景图 | 分类附件 `OVERVIEW` | 否，最多2张 |
| 学生实验图 | 分类附件 `STUDENT` | 否，最多3张 |

当前总结没有“实际参加人数”和“实际分组数”录入字段；显示的是预约分组数。提交总结只完成当前班级的计划实验，不改变整个实验计划。

任课教师可修改本人总结，学校管理员可修改本校总结。学校管理员删除总结时，分类图片一并移除；若存在独立业务附件则阻止删除。删除成功后，安排、预约和班级执行状态统一恢复为“已安排”，避免统计继续计入实开。

### 5.7 统计口径

```text
实验计划
  → 计划明细
  → 按适用班级形成班级执行记录（应开）
  → 预约
  → 管理员安排
  → 总结前耗材校验（如有数量型耗材）
  → 实验总结
  → 对应班级执行记录已完成（实开）
  → 学校／区级统计
```

- 应开数来自已发布计划实验与适用班级的组合，不是计划单据数或目录条目数。
- 实开数只统计状态为“已完成”的班级执行记录。
- 必做／选做和分组／演示均来自计划明细，两组维度分别统计。
- 分母为0显示“不适用”。

## 7. v12 当前数据结构

```text
学校
├─ 部门 ─ 人员（demo内含账号角色）
├─ 班级 ─ 任课关系（学期＋学科＋教师）
├─ 学校节次（按学期分版）
├─ 实验室／通用地点（底层 `rooms`）
├─ 设备／耗材业务台账
│  ├─ 单件资产 ─ 仪器设备维修登记／仪器设备报废登记
│  └─ 数量库存 ─ 易耗品总账／分类账／损耗登记
├─ 教材 ─ 官方实验目录
├─ 学校自定义创新实验（含结构化器材需求）
├─ 实验计划 ─ `planTargets`（显式适用班级） ─ 计划实验 ─ 班级执行记录（内部）
                         └─ 预约 ─ 安排 ─ 总结 ─ 统计
└─ 教学资源库（资源类型／学科／年级／实验属性）
```

数据版本为 v12。浏览器发现旧 v2 至 v11 数据时会在内存中迁移；旧实验目录同步转换为教材与官方实验目录，旧维修、维保和报废状态记录转换为维修或报废直接登记，取消和驳回记录不进入当前登记台账，旧损耗记录移除复核、状态及实验关联字段。迁移会补齐橱柜主档和 `storageMoves` 表，历史记录没有柜位时保留为房间直接存放。教学资源使用独立 `resources` 表，教师新上传的文件不写入旧业务附件表，也不进入待整理历史资料。其他历史计划、人员和房间数据仍按既有规则迁移并保留记录 ID 与操作日志；不存在入库单的历史可选来源编号会被清空，迁移结果必须通过关系审计。

较早版本已经写入 `version: 11` 的初始演示库也会执行幂等补齐。系统只对识别出的 demo 初始数据补充缺失的科学教材与目录、每校科学教师、科学实验室、科学设备、当前学期有效任课、科学计划、显式 `planTargets`、计划实验和内部班级执行记录，并补齐三个年级的选择数据；已有记录优先复用，补齐完成后写入标记，避免重复插入或在以后反复重建用户主动删除的示例。

重置后的 v12 seed 基线在原有数据上增加每校4个橱柜，共12个橱柜；资产和库存示例均带有房间内柜位。其余核心演示数据规模保持原口径，位置调整记录在实际移柜后产生。

## 8. 当前 demo 边界

- 数据保存在浏览器 `localStorage`，身份保存在当前窗口 `sessionStorage`；没有服务端数据库、真实并发和防篡改审计。
- 人员、账号和角色为便于演示仍合并，不能作为生产权限模型。
- 计划保存即发布，没有独立草稿和版本审批界面；无执行痕迹时允许管理员直接更正原计划字段。计划项来自教材实验目录，属性固定区分必做、选做、创新实验；适用班级保存到 `planTargets`。
- 采购按整单到货，不支持部分收货。
- 导入为UTF-8 CSV，不直接读取XLSX。
- 当前不建设设备借用归还业务；维修登记不改变设备状态，报废登记直接把对应设备标记为已报废。
- 实验室/通用地点状态在主档中维护；当前没有实验室改造和摄像头配置表单。
- 数量库存当前按“物品＋房间＋橱柜”维护余额，有效期是该余额的管理属性；管理员移柜时转移数量并保留位置调整记录；正式危化品系统还应扩展为批次号、批次有效期和近效期优先出库。
- 官方目录器材在计划发布时形成快照；创新实验可维护 `equipmentRequirements`（名称、规格、单位、数量、备注）并允许使用未建档器材。自定义器材只作为教学需求，不自动写入设备或库存台账。
- 图片和业务附件保存在浏览器，适合演示数据，不适合真实敏感资料。
