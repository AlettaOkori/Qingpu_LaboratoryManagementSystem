# v9 表单字段与数据关系对照

核对日期：2026-09-02。

核对范围为参考系统的物理实验室和通用模块，以及当前 `new-demo` v9 的实际代码。其他学科只复用同一套结构，不在本文重复展开。参考系统未展示的下拉枚举、后台必填规则和审批条件，不作为已确认事实。

本次对当前部署版本重新核验后，确认以下页面事实：

- “任课教师设置（物理）”页面以年级为入口，维护班级名称和任课教师；页面没有学期、学科、主教师和状态字段。
- “编制实验计划（物理）”页面显示当前学期，并包含选择年级、计划名称、可选教材、适用班级和实验条目；教材落在实验条目维度。
- 预约与安排仍是两个业务动作，但统一放在“预约与安排”模块中用页签切换；管理员安排时才确定最终地点和时间。
- 当前部署仍保留“橱柜登记（物理）”“存放到橱柜（物理）”“橱柜卡”等页面，并在橱柜存放明细中使用“层次”。这些是参考系统现状，不是新 demo 要继承的设计。

本文状态含义：

- **保留**：参考字段在 demo 中以相同或等价语义使用。
- **上下文自动写入**：界面只读展示或不显示，保存时由当前学校、学期、学科或账号写入。
- **筛选不入库**：只用于缩小可选范围，不在业务记录中重复保存。
- **删除／拆分**：从原表单移走，或改由独立关系、独立业务记录表达。
- **新增**：参考截图中未出现，但当前 demo 为本地业务闭环实际增加的字段。

## 1. 已确定的统一规则

### 1.1 界面称“实验室”，底层统一使用 `rooms`/`roomId`

参考系统在入库、存放、调整、报废等页面使用“房间或橱柜”和“层次”。当前 demo 将原合并入口改为“实验室”：实验室页只提供实验室档案；“班级管理”和“任课教师设置”归入“人员管理”。

为兼容教学实验室、准备室、仪器室、普通教室和其他地点，底层数据表仍使用 `rooms`，资产和库存仍通过 `roomId` 关联位置。这里的“实验室”是学校端主档入口的界面名称，不表示发生了数据迁移。

当前 demo 已作如下统一：

- 用户界面、台账、导入模板和业务关系只使用单层“存放位置”；在底层关系中，该位置由 `rooms`/`roomId` 表达。
- 不建立橱柜、层次、橱柜卡或橱柜二维码数据。
- 设备和库存均直接关联 `roomId`，不再通过实验室档案间接推导位置。
- 入库时允许房间为空；单件设备进入“待存放”，数量库存进入“待分配”。
- 后续“分配存放位置”只选择房间；已有同物品同房间库存时合并余额。

### 1.2 表单值只保留一个权威来源

- 实验名称、章节、年级、教材、器材需求和课时由学校实验计划直接维护；不再依赖独立实验目录。
- 分类编号、物品名称、规格、分类、单位、跟踪方式和维保要求直接随采购、入库和台账明细保存。
- 班级、教师和学科关系来自任课班级设置。
- 节次的开始、结束时间来自学校节次。
- 计划、预约、安排和总结不重复抄写上述主数据，只保存关联ID和必要业务快照。

### 2.4 班级与任课教师设置

参考系统“任课教师设置”按年级维护班级名称和任课教师，页面不显示学期、学科、主教师或状态。当前 demo 在“任课教师”列表中提供“设置任课班级”，将这些补成独立、可追溯的任课班级设置，班级表单不再直接多选教师。

在学校端，班级管理和任课教师设置均位于“人员管理”页签中；“实验室”页不承载班级管理或任课教师设置。

| 表单 | 字段 | 必填 | 处理 |
| --- | --- | --- | --- |
| 班级 | 所属学校、班级名称、年级、学生人数、状态 | 是 | 班级只保存班级自身属性 |
| 任课班级设置 | 学期、班级、学科、任课教师、是否主教师、状态 | 是 | 独立 `assignments` 关系；界面从任课教师进入，学期用于保留历届任课，主教师用于确定应开任务的唯一归属 |

同一学校内班级名称唯一。同一学期、班级和学科只允许一个有效主教师；任课教师必须是本校启用的教师账号。计划发布和新增有效任课班级设置时，系统据此生成班级实验任务。班级或任课班级设置一旦生成任务，不能直接改写会改变历史含义的年级、学期、学科、教师和主教师属性；存在在途任务时不能停用。

### 2.5 学期与学校节次

| 表单 | 字段 | 必填 | 用途 |
| --- | --- | --- | --- |
| 学期 | 学期名称、开始日期、结束日期 | 是 | 计划上下文、日期范围和统计范围 |
| 学校节次 | 当前学期（上下文）、节次编号、名称、开始时间、结束时间、状态 | 是 | 以“学校＋学期＋节次编号”分版；同版编号和时间段均不得重叠，预约中不重复填写起止时间 |

节次一旦被同学期预约或安排引用，所属学校、学期、编号、起止时间和状态均锁定，防止历史申请与安排时间被基础数据反向改写。

房间已有存放物品时不能直接修改学科；仍有危化品库存时不能取消危化品存放条件；存在有效安排时不能修改类型、学科、座位数或停用。上述限制用于保护存量台账与历史安排，不是参考登记页的原始字段。

### 3.2 设备与耗材业务明细

v9 不设置独立的“物品目录”页面。设备名称、分类编号、规格型号、分类、单位、管理方式和周期维保要求由采购、入库和库存／设备台账明细直接保存，并在后续业务中保留当时快照。

| 明细位置 | 必填字段 | 业务作用 |
| --- | --- | --- |
| 采购申请明细 | 分类编号、名称、规格型号、分类、单位、管理方式、数量、单价 | 形成采购申请和到货入库依据 |
| 入库明细 | 上述物品字段、房间、下次维保日期、有效期 | 生成设备资产或数量库存 |
| 设备台账／库存 | 物品字段、设备编号或库存数量、房间、状态 | 追踪当前资产、库存和处理状态 |

组合约束：耗材和危化品必须按数量库存管理，危化品另执行双人复核；“需要周期维保”只适用于单件编号设备。表单和事务层都会校验无效组合。
## 4. 采购、入库与存放

### 4.1 采购申请

采购审批是青浦本地业务扩展，不是参考物理模块截图中的核心表单。

| 字段 | v9处理 | 必填 |
| --- | --- | --- |
| 采购用途、申请日期 | 用户填写 | 是 |
| 物品明细（分类编号、名称、规格、分类、单位、管理方式）、数量、单价 | 明细填写 | 是 |
| 名称、分类编号、规格、分类、单位 | 由明细直接填写并写入快照 | 是 |
| 申请人、学校、申请单号、状态 | 当前账号和系统自动写入 | 自动 |
| 存放房间、维保日期 | 采购阶段删除 | — |

学校管理员提交，区级管理员通过或驳回；已通过采购单按当前 demo 规则整单到货，不支持部分收货。

### 4.2 入库单

| 参考字段 | v9字段及处理 | 必填 | 差异原因 |
| --- | --- | --- | --- |
| 入库单号 | 保存后自动生成，只读说明 | 自动 | 防止手工重复编号 |
| 供应商 | `supplier` | 是 | 保留 |
| 购置日期 | `purchaseDate` | 是 | 保留，不能晚于登记日期 |
| 登记日期 | `date` | 是 | 保留 |
| 经手人 | 当前账号自动写入 `operator` | 自动 | 不允许冒填 |
| 备注 | `note` | 否 | 保留，最多500字 |
| 分类编号 | 明细直接填写分类编号 | 是 | 避免手输错误 |
| 名称、规格、分类、单位 | 由明细直接填写 | 是 | 单一数据来源 |
| 数量、单价 | 明细填写 | 是 | 保留 |
| 总价 | 数量×单价计算 | 自动 | 不单独录入 |
| 房间或橱柜 | 仅保留 `roomId`，标签为存放位置（房间） | 否 | 空值进入待存放／待分配 |
| 层次 | 删除 | — | 不使用橱柜 |
| 下次维保日期 | 明细字段 `nextMaintenance` | 条件可选 | 只允许需维保的单件设备填写，不再放在单据头 |
| 有效期 | 明细字段 `expiry` | 危化品必填 | 只用于数量库存；危化品有效期不得早于登记日期 |

审批采购单到货时，物品、数量和单价沿用已审批明细；表单只补房间、符合条件的维保日期及数量库存有效期。危化品到货必须登记有效期；未清零的过期余额不能与新到货混存。

CSV模板为12列，与入库弹窗中的物品明细字段一致：分类编号、物品名称、规格型号、分类、单位、管理方式、需要周期维保、数量、单价（元）、存放位置（房间）、下次维保日期、有效期。管理方式填写“单件设备”或“数量库存”，维保要求填写“是”或“否”；物品字段直接随入库明细保存，不再依赖独立物品目录。供应商、登记日期、购置日期和备注仍在入库弹窗中填写。

### 4.3 入库后的分流

```text
采购申请
  → 区级审批
  → 到货入库
      ├─ 单件编号物品 → 按数量生成资产编号
      │    ├─ 已选房间 → 正常使用
      │    └─ 未选房间 → 待存放 → 分配存放位置（房间）
      └─ 数量库存物品 → 建立/合并库存余额
           ├─ 已选房间 → 在库
           └─ 未选房间 → 待分配 → 分配房间/合并余额
```

含危化品的到货入库按整单处理：所有数量库存明细先形成待复核流水，单件资产也仅暂存为待复核状态。第二人全部复核通过后才统一记账、激活资产并更新入库单/采购单；任一明细驳回则整单撤销，采购单退回“已通过”以便更正后重新收货，驳回流水保留审计。若同一物品和房间已有未过期余额，合并后以较早有效期作为保守提醒；正式系统仍应按批次拆分。

### 4.4 设备业务表单

| 表单 | 当前字段 | 当前闭环 |
| --- | --- | --- |
| 入库建账 | 分类编号、名称、规格、分类、单位、管理方式、需要周期维保、数量、单价、房间、下次维保日期、有效期 | 入库时直接生成资产台账或库存余额；房间留空则保留待存放／待分配状态 |
| 维修／维保／报废登记 | 多选设备、处理类型、登记日期、期望处理日期、经办人只读、原因 | 维修直接进入处理；报废进入区级审批；维保先形成待执行计划，开始执行后才占用资产 |
| 维修／维保完成 | 完成日期、服务单位、金额、处理内容 | 转待验收 |
| 验收 | 验收意见、下次维保日期可选 | 通过后设备恢复正常使用；仅需周期维保物品可填下次维保日期，且须晚于本次完成日期 |

### 4.5 数量库存与流水

| 表单 | 当前字段 | 规则 |
| --- | --- | --- |
| 新增数量库存 | 分类编号、名称、规格、分类、单位、管理方式、补库阈值、初始房间可选、有效期 | 只允许数量型物品；位置可稍后分配；危化品必须登记未过期的有效期，且只能选择具备危化品存放条件的房间 |
| 维护库存 | 补库阈值、有效期 | 已有库存不能直接换物品或房间 |
| 位置管理 | 入库明细中的房间 | 入库时直接填写；留空则保留待分配状态 |
| 入库/领用/损耗/处置 | 物品、业务类型、数量、日期、原因 | 关联实验安排只在“领用”时可选；待复核出库占用可用量；关联安排的领用必须命中安排资源且不得超过配置量 |
| 退回 | 同上，另选原领用单 | 只能退回同物品已记账领用，累计不超过原数量；安排和任务从原领用单继承 |
| 复核 | 通过/驳回、复核意见 | 所有危化品库存流水及所有教师领用均需第二人复核，不能自审 |

实验安排中的数量型耗材必须存在足量、已记账并关联该安排的领用流水，才能提交实验总结。取消安排时自动撤销关联待复核领用；已记账领用须先按原单全量“退回”。只有退回保存 `sourceFlowId`；入库、领用、损耗和处置不保存来源流水，不能冒充退回。

预约补充需求直接保存设备／耗材明细，不会选中某一批过期余额；预约表单支持动态添加、删除计划外器材行并填写数量。管理员安排时不能选过期危化品库存作为实际器材。过期危化品库存不得领用、新增流水入库或通过在途领用复核；库存流水只允许真实退回、损耗和处置；阈值维护仍可用于存量管理；新到货也不能与尚未清零的过期余额混存。

## 5. 实验教学表单

### 5.1 实验计划

参考系统编制页显示当前学期，并提供年级、计划名称、教材、适用班级和实验条目等内容。结合当前业务口径，demo 将“实验计划”作为学校自己的完整业务单据：计划头保存适用年级和教材版本，计划明细保存实验名称、章节、器材需求和课时，不再通过独立实验目录间接解释实验。

学期和学科作为系统作用域自动写入；适用班级从计划删除，改由同学期、同学科的有效主教师任课班级设置派生班级实验任务；实验员角色并入学校管理员。学校端班级管理和任课教师设置均在“人员管理”中维护。

| 页面内容 | v9处理 | 是否写入计划 |
| --- | --- | --- |
| 当前学期 | 页面只读；保存时自动写入 `term` | 是，系统写入 |
| 当前学科 | 当前模块或教师专业上下文；综合教师使用页面所选具体学科。自动写入 `subject` | 是，系统写入 |
| 适用年级 | 计划头保存 `grade` | 是 |
| 教材版本 | 计划头保存 `version` | 是 |
| 计划名称 | 用户填写 `name` | 是 |
| 创建人、创建时间、发布时间、状态 | 系统自动写入 `createdBy/createdAt/publishedAt/state`，用于审计与发布／归档生命周期；`createdBy` 不是任课教师关系 | 自动 |
| 实验名称、章节、器材需求、课时 | 学校直接填写到计划明细 `experimentName/chapter/equipment/periods` | 是 |
| 实验属性 | 每项选择必做／选做，保存到计划明细 `required` | 是 |
| 实验类型 | 每项选择分组／演示，保存到计划明细 `mode` | 是 |
| 时间填写方式 | 每项选择周次或日期 | 是 |
| 计划周次 | 选择周次时保存 | 条件写入 |
| 计划日期 | 选择日期时保存 | 条件写入 |
| 适用班级 | 参考计划表单存在；v9删除。避免计划重复选班级和教师，发布后由有效主教师任课关系自动生成班级实验任务 | 否（不写入） |
| 任课教师 | 已从计划表单删除 | 否 |
| 计划完成状态 | 不存在 | 否 |

每条计划明细保存 `experimentName`、`chapter`、`equipment`、`periods`、`required`、`mode`、`scheduleType`，并只在 `plannedWeek` 与 `plannedDate` 中写入一种；表单会随时间填写方式禁用另一字段。计划明细还保留计划的学科、年级和教材语义，归档后无需查找其他目录即可还原；预约、安排和总结只引用计划明细并保存各自必要的业务快照，不重复维护实验主数据。

保存按钮的实际语义为“保存并发布”。同一学校、学期和学科可以按年级或教材建立多份计划；为防止应开分母翻倍，所有未归档计划之间都不能重复纳入相同“实验名称＋章节＋教材范围＋实验类型”，计划名称在同一学期和学科内也不能重复。计划归档后，该名称和实验明细可以在新版计划中重新使用。

计划可在没有在途任务时归档：未开展任务转为“已失效”，已完成任务作为历史保留；待安排、待修改或已安排等在途任务会阻止归档。

删除由学校管理员执行并要求填写删除原因。只有完全没有预约、安排、总结、库存流水、附件或在途任务的计划才允许删除，删除时连带移除计划明细和未开展班级任务；已有业务痕迹的计划必须归档。班级实验任务只有“待预约／已失效”且无预约、安排、流水或附件时可删除，已取消任务因保留预约历史不提供删除入口。

### 5.2 计划明细与班级实验任务

计划发布后，系统把每条计划明细与以下有效任课关系匹配：

- 同一学校；
- 同一学期；
- 同一学科；
- 任课关系为有效主教师（协同教师不进入应开分母）；
- 班级年级与计划头适用年级一致。

匹配后自动生成 `teachingTasks`，字段包括计划明细、任课关系、班级、教师、学期和任务状态。它不是用户录入表单，是班级应开次数、预约入口和完成状态的唯一载体。

同一班级、学期、计划实验（名称、章节、教材范围）和实验类型若已经完成，即使后续发生教师交接或计划归档重建，也不再重复生成一条新的应开任务；未完成任务仍随有效主教师任课关系正常生成。

### 5.3 实验预约

| 参考预约内容 | v9字段及处理 | 必填 |
| --- | --- | --- |
| 预约时间 | `submittedAt` 系统自动记录 | 自动 |
| 任课教师、预约人 | 从任务和当前账号带入，只读说明 | 自动 |
| 实验内容 | 选择班级实验任务 `taskId`；计划、班级、教师、章节、名称、器材只读展示 | 是 |
| 实验类型 | 从计划明细带入 | 自动 |
| 班级 | 从任务带入，不在预约中另选 | 自动 |
| 申请日期 | `requestedDate` | 是 |
| 申请时间 | 选择学校节次 `requestedPeriod` | 是 |
| 申请时班级人数 | `studentCount` 从班级主档保存快照 | 自动 |
| 分组数 | `groups` | 分组实验必填；演示实验不显示 |
| 补充实验仪器 | `requestedResources[].itemId + qty`，按设备／耗材明细选择需求数量 | 否 |
| 备注 | `note`；一次批量提交的各条预约共用 | 否，最多100字 |
| 实验室、最终时间、实验负责人 | 从预约删除 | — |

补充器材在预约阶段只表达物品类型和数量需求，不绑定具体设备编号、库存余额或房间，也不占用库存。表单默认一行空白需求，可点击“添加补充器材”继续添加，点击“移除”删除；最多30项。候选物品必须与实验学科相容，危化品只允许化学实验申请；实际安排再次按相同规则校验物品及其存放房间。提交后状态为“待安排”，不再使用“待审批／通过”冒充安排流程。

### 5.4 实验安排

管理员在“预约与安排”的“已预约实验”页签中打开安排表单，查看预约和计划上下文，并填写：

| 字段 | 必填规则 |
| --- | --- |
| 实际安排日期 | 必填，须在计划学期内 |
| 开始节次、结束节次 | 必填，来自本校启用节次；须连续且数量不少于计划明细课时 |
| 地点类型 | 必填：实验室、教室、其他 |
| 房间 | 实验室／教室时必填；实验室限学科匹配的可用教学实验室，教室限可用普通教室；已登记座位数时须满足班级容量。选择“其他”时禁用并清空 |
| 其他地点说明 | 仅地点类型为“其他”时必填；选择实验室／教室时禁用并清空 |
| 实验负责人 | 必填，限本校启用的学校管理员 |
| 实际配置器材 | 可选；在安排阶段确定实际资源并校验并发占用 |
| 安排说明 | 可选，最多100字 |

系统校验房间容量、实验室学科、班级、教师、实验负责人、房间和器材的时间冲突。学校管理员也可以在安排前退回预约；教师或学校管理员可修改申请日期、节次、分组数、补充器材需求和备注后重新提交。

### 5.5 安排后执行与总结前校验

参考系统在“安排实验”后直接进入“登记实验总结”，没有独立的准备表单、准备人或“已准备”状态。当前 demo 同样不抽离准备动作：管理员在安排表单中一次性确认房间、负责人和实际器材；数量型耗材如已配置，须在提交总结前完成关联领用流水的复核和记账。取消安排前，已记账领用必须按原单足量真实退回，待复核领用由系统撤销。

#### 5.5.1 预约与安排页签

预约和安排不拆成两个菜单，统一在“预约与安排”模块中通过页签切换。六个页签均从同一条预约—安排—总结关系计算，不新增重复表或重复状态：

| 页签 | 查询条件 | 与其他页签的关系 |
| --- | --- | --- |
| 已预约实验 | 预约状态为“待安排”或“已退回” | 管理员待安排队列；安排后移出本页 |
| 已安排实验 | 存在状态不是“已取消”的实验安排 | 包含当前已安排和已完成历史 |
| 待登记总结实验 | 安排状态为“已安排”，且没有对应 `summaries.arrangementId` | “已安排实验”的待办子集 |
| 我预约的实验 | `applicantId` 为当前账号，且预约仍为“待安排”或“已退回” | 个人预约待办，不重复显示已安排历史 |
| 我的已安排实验 | 当前账号为 `technicianId` 或 `arrangedBy` | 责任人视图，包含完成历史 |
| 我的待登记总结实验 | 同时满足“我的已安排实验”和“待登记总结实验” | 个人总结待办子集 |

“完成记录”不再单列页签，已完成安排保留在“已安排实验／我的已安排实验”中，通过“已完成”状态筛选查看。页签只改变列表范围，不改变 `bookings`、`arrangements` 或 `summaries` 的业务状态。

### 5.6 实验总结

参考系统展示实验名称、类型、分组数、时间、班级、装置图、器材、实验效果、改进意见、仪器完好情况、备注和分类图片。v9 当前表单如下：

| 字段 | v9处理 | 必填 |
| --- | --- | --- |
| 实验、类型、班级、教师、安排时间、房间、预约分组数、器材需求 | 关联数据只读展示 | 自动 |
| 实际完成日期 | `actualDate`，不得早于安排日期或晚于统计日期 | 是 |
| 实验效果 | `effect` | 是 |
| 改进意见 | `improvement` | 否 |
| 仪器完好情况 | `equipmentCondition` | 是 |
| 备注 | `note` | 否 |
| 实验全景图 | 分类附件 `OVERVIEW` | 否，最多2张 |
| 学生实验图 | 分类附件 `STUDENT` | 否，最多3张 |

当前总结没有“实际参加人数”和“实际分组数”录入字段；显示的是预约分组数。提交总结只完成当前安排和对应班级实验任务，不改变整个实验计划。

### 5.7 统计口径

```text
实验计划
  → 计划明细
  → 按有效任课关系自动生成班级实验任务（应开）
  → 预约
  → 管理员安排
  → 总结前耗材校验（如有数量型耗材）
  → 实验总结
  → 班级实验任务已完成（实开）
  → 学校／区级统计
```

- 应开数来自已发布计划下的班级实验任务，不是计划数或目录条目数。
- 实开数只统计状态为“已完成”的班级实验任务。
- 必做／选做和分组／演示均来自计划明细，两组维度分别统计。
- 分母为0显示“不适用”。

## 7. v9 当前数据结构

```text
学校
├─ 部门 ─ 人员（demo内含账号角色）
├─ 班级 ─ 任课关系（学期＋学科＋教师）
├─ 学校节次（按学期分版）
├─ 实验室／通用地点（底层 `rooms`）
├─ 设备／耗材业务台账
│  ├─ 单件资产 ─ 查看／维修／维保／报废
│  └─ 数量库存 ─ 入库／领用／退回／损耗／处置
└─ 实验计划 ─ 计划明细 ─ 班级实验任务
                         └─ 预约 ─ 安排 ─ 总结 ─ 统计
```

数据版本为 v9。浏览器发现旧 v2/v3/v4/v5/v6/v7/v8 数据时会在内存中迁移为地点主档、设备／耗材业务台账、任课关系、计划明细、班级任务、安排和总结结构；历史人员培训字段会被清理，历史“已准备”或“待总结”状态统一转换为“已安排”，旧准备说明保留在安排说明中；旧全局实验目录摊平为计划头/计划明细字段，旧“实验员”身份转换为学校管理员，再写回当前存储键。迁移保留旧记录 ID 映射和操作日志。

## 8. 当前 demo 边界

- 数据保存在浏览器 `localStorage`，身份保存在当前窗口 `sessionStorage`；没有服务端数据库、真实并发和防篡改审计。
- 人员、账号和角色为便于演示仍合并，不能作为生产权限模型。
- 计划保存即发布，没有独立草稿编辑和版本审批界面。
- 采购按整单到货，不支持部分收货。
- 导入为UTF-8 CSV，不直接读取XLSX。
- 当前不建设设备借用归还业务；设备状态只沿设备台账、维修、维保和报废流程变化。
- 实验室/通用地点状态在主档中维护；当前没有实验室改造和摄像头配置表单。
- 数量库存当前仍按“物品＋房间”维护余额，有效期是该余额的管理属性；正式危化品系统还应扩展为批次号、批次有效期和近效期优先出库。
- 计划明细器材需求是学校填写的文本；预约补充器材以设备／耗材明细和需求数量表达，支持动态新增/删除，管理员安排时才落实具体设备或库存余额。
- 图片和业务附件保存在浏览器，适合演示数据，不适合真实敏感资料。
